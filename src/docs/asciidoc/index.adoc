로컬 요청에서는 예시의 `https://docs.example.com`과 `http://localhost:8080`을 서버 주소로 바꿉니다.

== 개요

=== 호출 방법

* *웹 앱*: GitHub 로그인 세션 쿠키로 부릅니다. GET이 아닌 요청은 `XSRF-TOKEN` 쿠키 값을 `X-XSRF-TOKEN` 헤더로 보냅니다.
* *에이전트·스크립트*: `Authorization: Bearer <토큰>`으로 부릅니다. MCP OAuth로 받은 `adt_a_` 액세스 토큰이나 설정 화면에서 발급한 `adt_s_` 스크립트 토큰을 씁니다. Bearer 요청에는 CSRF 헤더가 필요 없습니다.
* 토큰은 승인할 때 고른 스페이스와 범위(`read`, `comment`, `edit`)만 다룹니다. 허용되지 않은 스페이스의 자료는 없는 것처럼 404로 답합니다.
* 로그인하지 않은 `/api/**`, `/mcp` 요청은 401이고, `WWW-Authenticate: Bearer resource_metadata="…", scope="read comment edit"` 헤더가 보호 리소스 메타데이터와 요청할 권한 범위를 알려 줍니다.
* 연결 하나당 1분에 600번까지 부를 수 있습니다. 넘으면 429와 `Retry-After`(초)를 돌려줍니다.

=== 오류 형식

오류는 `application/problem+json`입니다. `code`는 기계가 읽는 값이고, `fix`는 에이전트가 스스로 고칠 수 있게 다음 행동을 알려 줍니다.

[cols="1,1,3"]
|===
|HTTP |code |뜻

|400 |invalid |요청 값이 규칙에 맞지 않음
|401 |unauthenticated |로그인이나 토큰이 없음
|403 |forbidden |연결 범위가 모자라거나 허용되지 않은 동작
|404 |not_found |없거나 볼 수 없는 자료
|404 |not_resolved |저장소·디렉터리에 맞는 스페이스를 찾지 못함. `candidates`를 함께 보냄
|409 |conflict |다른 쪽이 먼저 고침. 블록 충돌이면 `conflicts`에 현재 블록을 보냄
|409 |taken |이미 쓰는 주소나 경로
|429 |rate_limited |요청이 너무 많음
|===

=== 멱등 키

쓰기 요청 본문에 `opId`를 넣으면 같은 `opId`로 다시 보낸 요청은 처음 결과를 그대로 돌려주고 두 번 쓰지 않습니다. 본문이 없는 쓰기(휴지통 이동·복원, 영구 삭제, 댓글 삭제)는 `opId`를 쿼리 파라미터로 받습니다. 네트워크가 끊겨 다시 보낼 때 씁니다.

=== 블록 형식

문서 본문은 블록 배열입니다. 모든 블록은 `id`(서버가 준 ID, 새 블록은 10자 `[a-z0-9]`), `type`, `hash`(본문 마크다운의 해시. 보낼 때는 빼도 됨)를 가집니다. 글 안의 서식은 마크다운으로 적습니다: `**굵게**`, `*기울임*`, `~~취소선~~`, `` `코드` ``, `[글](https://…)`, 문서 링크 `[제목](doc:<문서 ID>)`, 줄바꿈 `<br>`, 멘션 `@login`.

[cols="1,3"]
|===
|type |필드

|heading |`level` 1~3, `text`
|paragraph |`text`
|listItem |`style`(bullet, numbered, task), `depth` 0~, `checked`(task), `text`
|quote |`text`
|callout |`kind`(note, tip, important, warning, caution), `text`
|code |`language`, `code`
|table |`columns[]`(`id`, `align`: none, left, center, right), `rows[]`(`id`, `cells[]`). 첫 행이 머리글
|image |`assetId`, `alt`, `caption`
|divider |없음
|===

에이전트는 같은 본문을 *주석 마크다운*으로 읽고 씁니다. 블록마다 `<!-- b:<id> h:<hash> -->` 주석이 붙어 블록 ID와 해시를 알려 줍니다.

=== 편집 연산

`POST /api/documents/{id}/edits`와 MCP `docs_edit`은 블록 단위 연산 목록을 한 번에 적용합니다. 하나라도 실패하면 아무것도 바꾸지 않습니다. `ifHash`는 읽을 때 받은 블록 해시이고, 그 뒤 블록이 바뀌었으면 409 `conflict`로 현재 블록을 돌려줍니다.

[cols="1,3"]
|===
|op |필드

|replace |`blockId`, `ifHash`, `markdown`(블록 하나 이상)
|insert |`markdown`, 위치(`after`: 블록 ID, `before`: 블록 ID, `at`: start 또는 end. 기본 end)
|delete |`blockId`, `ifHash`
|move |`blockId`, `ifHash`, 위치
|replaceText |`blockId`, `find`, `replace`. `find`는 그 블록 마크다운에 정확히 한 번 나와야 하고, 바꾼 결과도 블록 하나여야 함
|===

== MCP

`POST /mcp` 하나로 JSON-RPC를 받는 무상태 Streamable HTTP 서버입니다. 공식 MCP Java SDK가 프로토콜을 처리하며, 프로토콜 버전 2025-11-25·2025-06-18·2025-03-26의 `initialize` 수명주기를 따릅니다. 세션 ID는 쓰지 않고 요청마다 JSON 응답 하나로 답합니다. 요청의 `Accept`에는 `application/json`과 `text/event-stream`이 모두 있어야 합니다. 스트림(`GET /mcp`)은 열지 않고 405로 답하며, 허용하지 않은 `Origin`은 403입니다.
