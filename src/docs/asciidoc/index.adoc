로컬 요청에서는 예시의 `https://docs.example.com`과 `http://localhost:8080`을 서버 주소로 바꿉니다.

== 개요

=== 호출 방법

* *웹 앱*: GitHub 로그인 세션 쿠키로 부릅니다. GET이 아닌 요청은 `XSRF-TOKEN` 쿠키 값을 `X-XSRF-TOKEN` 헤더로 보냅니다.
* *에이전트·스크립트*: `Authorization: Bearer <토큰>`으로 부릅니다. MCP OAuth로 받은 `adt_a_` 액세스 토큰이나 설정 화면에서 발급한 `adt_s_` 스크립트 토큰을 씁니다. Bearer 요청에는 CSRF 헤더가 필요 없습니다.
* 토큰은 승인할 때 고른 스페이스와 범위(`read`, `comment`, `edit`)만 다룹니다. 허용되지 않은 스페이스의 자료는 없는 것처럼 404로 답합니다.
* 로그인하지 않은 `/api/**`, `/mcp` 요청은 401이고, `WWW-Authenticate: Bearer resource_metadata="…", scope="read comment edit"` 헤더가 보호 리소스 메타데이터와 요청할 권한 범위를 알려 줍니다.
* 연결 하나당 1분에 600번까지 부를 수 있습니다. 넘으면 429와 `Retry-After`(초)를 돌려줍니다.

=== 오류 형식

오류는 `application/problem+json`입니다. `code`는 기계가 읽는 값이고, `fix`는 에이전트가 스스로 고칠 수 있게 다음 행동을 알려 줍니다.

[cols="1,1,3"]
|===
|HTTP |code |뜻

|400 |invalid |요청 값이 규칙에 맞지 않음
|401 |unauthenticated |로그인이나 토큰이 없음
|403 |forbidden |연결 범위가 모자라거나 허용되지 않은 동작
|404 |not_found |없거나 볼 수 없는 자료
|404 |not_resolved |저장소·디렉터리에 맞는 스페이스를 찾지 못함. `candidates`를 함께 보냄
|409 |conflict |다른 쪽이 먼저 고침. 블록 충돌이면 `conflicts`에 현재 블록을 보냄
|409 |taken |이미 쓰는 주소나 경로
|429 |rate_limited |요청이 너무 많음
|500 |export_incomplete |첨부 원본이 없어 완전한 내보내기를 만들지 못함. 첫 실패 첨부와 `scanComplete: false`를 보냄
|===

=== 멱등 키

쓰기 요청 본문에 `opId`를 넣으면 같은 `opId`로 다시 보낸 요청은 처음 결과를 그대로 돌려주고 두 번 쓰지 않습니다. 본문이 없는 쓰기(휴지통 이동·복원, 영구 삭제, 댓글 삭제)는 `opId`를 쿼리 파라미터로 받습니다. 네트워크가 끊겨 다시 보낼 때 씁니다.

=== 블록 형식

문서 본문은 블록 배열입니다. 모든 블록은 `id`(서버가 준 ID, 새 블록은 10자 `[a-z0-9]`), `type`, `hash`(본문 마크다운의 해시. 보낼 때는 빼도 됨)를 가집니다. 글 안의 서식은 마크다운으로 적습니다: `**굵게**`, `*기울임*`, `~~취소선~~`, `` `코드` ``, `[글](https://…)`, 문서 링크 `[제목](doc:<문서 ID>)`, 줄바꿈 `<br>`, 멘션 `@login`.

[cols="1,3"]
|===
|type |필드

|heading |`level` 1~3, `text`
|paragraph |`text`
|listItem |`style`(bullet, numbered, task), `depth` 0~, `checked`(task), `text`
|quote |`text`
|callout |`kind`(note, tip, important, warning, caution), `text`
|code |`language`, `code`
|table |`columns[]`(`id`, `align`: none, left, center, right), `rows[]`(`id`, `cells[]`). 첫 행이 머리글
|image |`assetId`, `alt`, `caption`
|drawing |`svgAssetId`(정리한 SVG 첨부), `sceneAssetId`(Excalidraw 장면 첨부), `alt`(한 줄 500자 이하). 마크다운은 `![alt](asset:<svgAssetId> "excalidraw asset:<sceneAssetId>")`. <<drawing,손그림>> 참고
|divider |없음
|===

에이전트는 같은 본문을 *주석 마크다운*으로 읽고 씁니다. 블록마다 `<!-- b:<id> h:<hash> -->` 주석이 붙어 블록 ID와 해시를 알려 줍니다.

=== 편집 연산

`POST /api/documents/{id}/edits`와 MCP `docs_edit`은 블록 단위 연산 목록을 한 번에 적용합니다. 하나라도 실패하면 아무것도 바꾸지 않습니다. `ifHash`는 읽을 때 받은 블록 해시이고, 그 뒤 블록이 바뀌었으면 409 `conflict`로 현재 블록을 돌려줍니다.

[cols="1,3"]
|===
|op |필드

|replace |`blockId`, `ifHash`, `markdown`(블록 하나 이상)
|insert |`markdown`, 위치(`after`: 블록 ID, `before`: 블록 ID, `at`: start 또는 end. 기본 end)
|delete |`blockId`, `ifHash`
|move |`blockId`, `ifHash`, 위치
|replaceText |`blockId`, `ifHash`, `find`, `replace`. `find`는 그 블록 마크다운에 정확히 한 번 나와야 하고, 바꾼 결과도 블록 하나여야 함
|===

=== 제목·경로·상태 바꾸기

머리 정보 변경도 `baseVersion`이 필수이며 현재 콘텐츠 버전과 다르면 409입니다. 웹은 변경하려는 필드가 다른 쪽에서 바뀌지 않았을 때 새 버전으로 재시도합니다.

경로의 앞부분은 상위 문서입니다. 경로를 바꾸면 그 아래 문서도 함께 옮기고, 새 경로에 없는 상위 문서는 빈 문서로 만듭니다. 자기 아래로는 옮길 수 없고, 옮겨 갈 경로 중 하나라도 쓰이고 있으면 아무것도 옮기지 않습니다. 문서를 만들 때도 없는 상위 문서를 빈 문서로 만듭니다.

== P1 확장 API

문서 저장·머리 정보·생성·편집·복원의 선택 `inputTrace`는 실제 전경 입력 구간이다. 통계는 문서 트랜잭션 성공 후 별도로 기록하며 잘못된 trace나 통계 장애는 저장 성공을 바꾸지 않는다.
`codeReferences`는 최대 20개이며 각 항목에 전체 40자리 commit SHA 또는 양의 PR 번호가 필요하다. repository 생략은 연결 레포가 정확히 하나일 때만 허용한다. 임의 URL이나 GitHub 토큰을 받지 않는다.
REST markdown은 별도 `agentGuide`를 반환하고 MCP는 원본 markdown 뒤의 별도 text content로 지침을 안내한다. 문서 markdown과 머리말은 바꾸지 않는다.
스페이스 변경의 `agentGuideDocumentId`, `defaultRepository`는 null이면 해제하고 생략하면 유지한다.
통계 응답은 human, agentExplicit, agentEstimated 각각 milliseconds와 count, 열린 구간 openCount를 제공한다. 통계는 편집 점유와 독립이다.
SSE는 현재 인증과 문서 가시성을 재검사하고 1초 조회, 15회 무변경 heartbeat, 300초 정상 종료 후 다시 연결한다. 응답 캐시와 proxy buffering을 끄고 proxy read timeout은 15초보다 길게 설정한다.

공개 `GET /oauth/clients/adocs`는 기존 사용자 승인, PKCE S256, scope와 resource 검증을 사용한다. 클라이언트 비밀은 없다.
비상 로그인은 발급 후 정확히 10분인 단회 허가를 CSRF 보호 POST로 소비한다. GET은 확인 화면만 제공하며 발급 REST/MCP는 없다.

=== 입력 통계 구간

선택 `inputTrace`의 새 형식은 `{batchId, traces:[{tabId,batchId,intervals:[{firstInputAt,lastInputAt}]}]}`다. 전체 요청 batchId는 재시도에도 고정한다. 서로 다른 foreground의 입력도 한 성공 version의 원자 batch로 채택하며, 잘못된 child나 기록 실패는 전체 통계 batch를 롤백하고 문서 성공은 유지한다.

기존 단일 `{tabId,batchId,intervals:[...]}` 형식도 child 한 개로 정규화하며 전체 batchId는 그 child batchId를 사용한다. 구간의 120초 이상 입력 공백은 별도로 보낸다. 호환 firstInputAt/lastInputAt 파생값은 intervals를 대신하지 않는다. no-op이나 이미 채택한 version·batch는 통계를 중복 기록하지 않는다.

[[memberships]]
=== 스페이스 멤버

사람 소유자만 씁니다. 에이전트는 소유자의 연결이어도 403 `forbidden`입니다. 쿠키 요청의 POST·PATCH·DELETE는 다른 쓰기처럼 `X-XSRF-TOKEN`이 필요합니다.

* 초대는 로그인 허용을 겸합니다. 수락 단계·메일·공개 링크는 없습니다. 초대받은 로그인이 처음 GitHub 로그인에 성공하면 `state`가 `pending`에서 `active`가 되고 그 GitHub 사용자 ID에 고정됩니다. `pending` 초대는 아무 스페이스 권한도 주지 않습니다.
* 역할 변경과 회수는 그 사람의 다음 요청부터 적용됩니다. 회수는 기록을 남기고 다시 살리지 않으며, 목록에는 살아 있는 멤버십만 나옵니다. 이미 회수한 멤버십을 다시 지워도 204입니다.
* `space`는 스페이스 UUID입니다. 서버는 존재를 확인하지 않으므로 화면은 스페이스 목록에서만 고르게 합니다.
* 새 초대의 `login`은 앞뒤 공백을 지운 뒤 1~39자 영문·숫자, 글자 사이 단일 하이픈만 받습니다. 대소문자는 그대로 저장하고 비교할 때는 무시합니다. 소유자 자신의 로그인과 형식 오류는 400 `invalid`이고, 같은 스페이스에 살아 있는 멤버십이 있으면 409 `conflict`와 기존 `membershipId`를 돌려줍니다. 이미 저장된 로그인은 예전 형식이어도 그대로 읽습니다.

[[permission]]
=== 응답의 권한

웹 앱의 사람은 소유자이거나, 소유자가 스페이스에 초대한 편집자·댓글 작성자입니다. 아래 응답의 `permission`은 요청한 사람이나 연결이 그 스페이스에서 지금 가진 권한(`read`, `comment`, `edit`, `owner`)이고, 화면은 이 값으로 편집·댓글 기능을 엽니다. 사람 소유자는 언제나 `owner`, 편집자는 `edit`, 댓글 작성자는 `comment`입니다. 최종 판정은 각 쓰기 요청에서 서버가 다시 합니다.

* 스페이스: <<_스페이스_목록,목록>>(원소마다), <<_스페이스_만들기,만들기>>, <<_스페이스_조회,조회>>, <<_스페이스_바꾸기,바꾸기>>, <<_저장소디렉터리로_스페이스_찾기,찾기>> 응답의 최상위 `permission`.
* 문서: <<_문서_열기,열기>>, <<_문서_만들기,만들기>>, <<_제목경로상태_바꾸기,제목·경로·상태 바꾸기>> 응답의 최상위 `permission`. 그 문서가 지금 있는 스페이스 기준입니다.
* 같은 `opId`로 다시 보낸 요청은 처음 결과를 그대로 돌려주지만 `permission`만은 지금 요청자와 문서가 지금 있는 스페이스로 다시 계산합니다.
* `/api/me`의 `owner`는 전역 소유자 여부 그대로이고 MCP 출력은 바뀌지 않습니다.
* 스레드 해결은 사람이 `edit` 이상이면 모든 스레드, `comment`면 자기가 연 스레드만 됩니다. 수정 제안 수락·거절은 `edit` 이상인 사람만 합니다. 영구 삭제는 사람 소유자만 합니다.

[[document-event-signals]]
=== 문서 변경 알림의 권한 신호

<<_document_events,문서 변경 알림>> 스트림은 `invalidate` 말고도 두 이벤트를 보냅니다. `data`는 JSON 문자열이고 본문·제목·스페이스 이름을 담지 않습니다. 권한 변경만으로 문서 버전은 바뀌지 않습니다.

[cols="1,2,3"]
|===
|event |data |뜻

|invalidate |`{}` |커밋된 문서 상태가 바뀜. 다시 조회합니다
|permission |`{"permission":"comment"}` |이 스트림에서 직전에 본 권한과 지금 권한이 다름. 연결 직후 첫 확인에는 보내지 않습니다
|revoked |`{"reason":"not_found"}` 또는 `{"reason":"unauthenticated"}` |이 문서를 더 볼 수 없음(회수, 볼 수 없는 스페이스로 이사, 삭제를 구분하지 않음) 또는 로그인이 더는 허용되지 않음. 보낸 뒤 서버가 스트림을 정상 종료하므로 클라이언트가 재연결을 멈춥니다
|===

[[drawing]]
=== 손그림

손그림 블록(`type: "drawing"`)은 정리한 SVG 첨부와 Excalidraw 장면 첨부 두 개를 가리킵니다. 둘 다 바뀌지 않는 첨부라서, 그림을 고치면 새 장면과 SVG를 올린 뒤 같은 블록 ID에 새 쌍을 저장합니다. 고치지 않은 장면 필드는 그대로 두어야 그린 원본이 유지됩니다.

* 장면은 <<_업로드,업로드>>나 업로드 토큰으로 `.excalidraw` 파일(`application/vnd.excalidraw+json`)로 올립니다. 서버 첨부 종류는 `EXCALIDRAW`입니다. @excalidraw/excalidraw 0.18.1이 쓰는 UTF-8 JSON이어야 하고, AI가 만든 HTML 프레임(`iframe` 요소)과 `data:` 주소가 아닌 이미지 파일은 400 `invalid`입니다. 바이트는 고치지 않고 저장합니다.
* 손그림은 `type: "drawing"` 블록으로만 만듭니다. `image` 블록의 `caption`이 정확히 `excalidraw asset:<UUID>`이면 400 `invalid`이고, 조금이라도 다른 캡션은 일반 이미지입니다.
* SVG는 다른 SVG처럼 스크립트와 바깥 참조를 지워 저장합니다. `<style>` 요소에 `data:`·`#`이 아닌 `url(`, `@import` 같은 외부 참조나 CSS 이스케이프(역슬래시)가 있으면 그 요소를 지웁니다. 원문 읽기와 내보내기도 정리된 바이트를 돌려줍니다. 첨부 응답의 CSP는 <<_내용,내용>>의 응답 헤더처럼 `sandbox`에 `data:` 이미지·폰트만 허용하므로, 손그림 SVG는 폰트를 `data:`로 담아야 글자가 보입니다.
* 문서 저장 때 SVG 자리에는 SVG, 장면 자리에는 장면 첨부만 받습니다. 대체 텍스트는 한 줄 500자 이하이고, 검색과 블록 전체 댓글 인용은 대체 텍스트만 씁니다. 글자 범위 댓글은 달 수 없습니다.
* 웹 앱은 장면과 SVG 원문을 그 그림이 든 문서를 거쳐 읽습니다(<<_document_assets_source,문서 범위 원문>>). 장면이면 텍스트 요소 목록 `texts`를 함께 돌려줍니다.
* 에이전트는 MCP `docs_upload`에 `assetId`와 그 그림이 든 `document`를 함께 보내 읽습니다. 문서 없이 손그림 첨부를 읽으면 오류입니다. SVG는 원문을, 장면은 기본으로 `texts`·`elementCount`·`fileCount`만 돌려주고 `includeSource: true`일 때만 저장된 장면 JSON(`source`)도 돌려줍니다.
* 읽기용 마크다운 내보내기를 다시 가져오면 손그림은 일반 SVG 이미지로 들어오고 장면은 복원되지 않습니다. 정본 JSON 내보내기에는 `drawing` 블록과 두 파일이 들어갑니다.
